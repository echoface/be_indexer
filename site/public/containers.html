01 · 两个正交轴：容器与编码器

IndexType 决定 posting 存在哪里、term 怎样被找到；Encoder 决定业务值怎样变成 term。它们可以自由组合，但必须与查询语义一致。

IndexTypeterm → posting

FlatDict 二分、MPH 常数哈希、FST 状态机、AC 自动机、Range 线段树。它们共享同一个 posting 原语。

Encodervalue → term

default 字符串恒等、number 整数、ext_range 区间、proximitygeo geohash 覆盖。编码失败会影响 Include 或 Exclude，生产建议开严格查询。

03 · Default FlatDict：排序数组上的二分

字段的去重 term 按字节序存放在一个扁平数组中。查找就是二分：term → 16 字节 item → {PostingOffset, PostingCount}。

figure 07<field>_dict
适合默认选择

精确等值 / IN / NOT IN；词表 ≤ ~1M；需要枚举、调试或反向查找；不想引入外部依赖。

不适合换容器

数值区间用 ext_range；子串筛选用 ac_matcher；超大高熵 key 用 mph_dict；超大结构化 key 用 fst_dict。

04 · mph_dict：常数时间，不存 key

CHD（Compress-Hash-Displace）为每个 key 分配一个无冲突槽位。查询做几次哈希与数组读取就能定位；term 字符串在构建后不再保留，只存 12 字节 posting 引用。

figure 08CHD · minimal perfect hash
!

安全边界：因为不存 term，MPH 无法验证查询 key 是否真的在构建集合里。最小完美哈希对任何输入都会返回某个槽位，absent key 可能碰撞到无关槽位。仅用于查询域可信，或能接受下游过滤少量假阳性 posting 的场景。

操作成本
Term lookupO(1) · 几次哈希 + 数组读（约 250 ns 常数）
Posting scan / mergeO(posting length) · galloping SkipTo
BuildO(n) 摊销 CHD 构建

05 · fst_dict：把共享结构折进状态机

FST（Finite State Transducer，基于 blevesearch/vellum）把 term 的共享前缀/后缀折叠成图。查找沿状态机走一遍，成本只与 term 长度有关，与词表大小无关。

figure 09prefix sharing

并发与零分配

vellum 的普通 FST.Get 每次调用分配内部 state；它的零分配 FST.Reader 又要求单线程。为同时满足“查询热路径不分配”和“MatchQuery 可并发”，Reader 维护一个 sync.Pool：每次查询借一个带可复用 state 的 *vellum.Reader，用完归还。池空时回退到分配的 FST.Get。

查询 key 通过零拷贝 unsafe.Slice 借用字符串字节；Get 只读且不保留引用。

词表规模命中未命中
100,000 terms~306 ns · 128 B · 5 allocs~19 ns · 0 B · 0 allocs
1,000,000 terms~257 ns · 128 B · 5 allocs~47 ns · 0 B · 0 allocs

来自 BenchmarkFST_Find 的参考机测量；延迟在 100K 与 1M 之间基本持平，说明与词表规模无关。命中路径的分配由 reader pool 与 vellum 内部行为决定，数字仅作相对参考。

06 · ac_matcher：一次扫描，命中所有模式

Aho-Corasick 把字段里的所有模式编译进一个自动机，用 Double-Array Trie 存储。查询文本走一遍，所有模式同时被匹配；成本由文本长度决定，而不是模式数量。

关键实现DAT
  • 1模式中出现的 rune 映射为稠密 symbol id，0 保留给未知字符，地址空间不随 Unicode 全量膨胀。
  • 2转移用 base[state] + symbolID，中间量 64 位，避免溢出伪造转移。
  • 3fail 链预先展平，输出沿 fail 链合并；terminal state 直接列出所有在该状态结束的模式。
磁盘布局<field>_ac_matcher

Header（stateCount / symCount）→ symbol table → base / check / fail / outputPtrs 并行数组 → output data（count + posting refs）。base/check 等数组在 aligned LE 上借用 mmap。

语义提醒：AC 是子串包含，不是整值相等。精确等值请用 default / mph / fst；数值区间请用 ext_range。

07 · ext_range：点索引 + 线段树

区间谓词本质是 stabbing query：查询一个点，找出哪些 Document 的区间覆盖它。构建器按形状拆分：等值折成退化区间 [v,v] 进入点索引；真正的区间进入线段树。

拖动滑块改变查询点。绿色为覆盖 q 的区间；真实实现中，点索引与线段树分别返回条目，二者构造上不相交，因此不会重复计数。

figure 10canonical decomposition
点索引P distinct keys

升序 int64 key 数组 + 并行 posting offset，无分配二分。等值、IN 走这里。

线段树m endpoints

只对真正的区间端点建树；每节点 24 字节：split i64 | left i32 | right i32 | postOff u32。查询点沿一条路径下推。

复杂度：点 O(log P)，树 O(log m)，posting 扫描 O(posting length)，构建 O((P+m) log(P+m))。空字段可省略 block。

08 · proximitygeo：把圆覆盖变成 term 匹配

它不是容器，而是编码器。文档侧的 (lat, lng, radius) 用 proximityhash 展开成覆盖圆的 geohash cell；查询点编码为 geohash，并展开为多个前缀。之后就是普通 FlatDict 等值查询。

figure 11radius → geohash covering
i

精度边界：这是 proximity，不是精确几何。geohash cell 是近似，受 maxQueryPrecision（约 38 m）和 radius→precision 表约束；半径必须在 (0, 1,000,000] 米内。

09 · 自定义容器：注册即可插拔

实现 IndexBuilder / IndexReader，在 init 注册；如果值还需要自定义编码，再注册一个 PredicateEncoder。跨 block 引用可实现 IndexValidator 做统一冷路径校验。

gocustom container
func init() {
    segment.RegisterIndex("my_index", segment.IndexDef{
        Reader:  newReaderFactory,
        Builder: newBuilderFactory,
    })
    parser.RegisterPredicateEncoder("my_index", encoderFactory)
}

// 可选：在 SegmentReader 解析完所有 block 后做跨块校验。

    return nil
